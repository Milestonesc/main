# Hermes Calendar

사용자의 개인 일정을 `hermes_calendar` MCP 도구로 다룬다. 일정은 구글의 'Hermes' 캘린더에 들어가고, 조회·겹침 확인·브리핑은 기본 캘린더까지 함께 본다.
아침 08:30 브리핑과 일정 직전 알림은 크론이 텔레그램으로 따로 보내므로, 이 스킬에서 알림을 직접 보낼 필요는 없다.

## 도구

| 도구 | 쓰는 때 |
|---|---|
| `today` | 날짜를 계산하기 전 항상 먼저. "내일", "다음주 화요일", "이번 달 말"을 YYYY-MM-DD로 바꾼다 |
| `add_event` | 일정 등록 (설명·메모·할 일도 같이) |
| `list_events` | 기간 일정 보기, `query`로 찾기 ("치과 언제였지?"), `status`로 거르기, `counts`로 상태별 개수 |
| `get_event` | 일정 하나 자세히: 상태, 설명, 할 일(번호), 메모, 기록 |
| `update_event` | 사용자가 **계획을 바꿀 때** (시간 옮기기, 제목·장소, 알림, 설명) |
| `set_status` | 상태 바꾸기: 예정 · 진행중 · 지연됨 · 완료 · 못함 · 취소 |
| `edit_notes` | 설명 바꿔 쓰기, 메모 덧붙이기, 할 일 추가·체크·해제·삭제 |
| `pending_review` | 끝났는데 결과가 안 남은 지난 일정 |
| `delete_event` | 사용자가 "지워/삭제"라고 분명히 말했을 때만 |
| `day_info` | 그날 쉬는 날인지(주말·공휴일·대체공휴일·근로자의 날·연차), 그날 일정 |
| `business_days` | "영업일 5일 뒤", "마감까지 영업일 며칠" |
| `dday` | "시험까지 며칠" |
| `briefing` | 하루 요약. "이번 주 어때?"는 `list_events` |
| `check_conflicts` | 등록 전에 시간만 확인하고 싶을 때 |

id는 `list_events`로 먼저 찾는다.

## 일정 상태

| 상태 | 표시 | 언제 |
|---|---|---|
| 예정 | | 새 일정 기본값 |
| 진행중 | ▶️ | 하고 있는 중 ("지금 회의 중", 여러 날 걸리는 일) |
| 지연됨 | ⏳ | **원치 않게 밀림** ("회의가 30분 밀렸어", "택배가 늦어져서 내일로") |
| 완료 | ✅ | 했음 |
| 못함 | ❗ | 시간이 지났는데 못 했음 ("못 갔어", "깜빡했어") |
| 취소 | ❌ | 하지 않기로 함 ("취소됐어", "안 가기로 했어"). 겹침 확인에서 빠진다 |

표시는 구글 캘린더 제목 앞에 붙고, 바뀔 때마다 일정 설명란 [기록]에 시각과 함께 남는다.

- **밀림과 변경을 구분한다.** 사용자가 스스로 옮기면("3시로 바꿔줘", "내일로 옮겨줘") `update_event` → 기록에 '시간 변경'. 원치 않게 밀렸으면("밀렸어", "늦어졌어", "연기됐어") `set_status(status="지연됨", start=새 시각)` → 기록에 '지연'. 새 시각을 모르면 start 없이 상태만 바꾼다. 모호하면 "일부러 옮긴 거예요, 밀린 거예요?"라고 묻는다.
- **결과·사유는 note로.** "치과 다녀왔어, 다음 진료 11/6" → `set_status(status="완료", note="다음 진료 11/6")`. 사용자가 말한 것만 쓰고 지어내지 않는다.
- **정리 안 된 일정.** 아침 브리핑에 "결과가 안 남은 지난 일정"이 나온다. 사용자가 "치과 완료, 회의는 취소"처럼 답하면 `pending_review`로 id를 찾아 각각 `set_status`. 사용자가 먼저 묻기 전에는 결과를 캐묻지 않는다.
- **"이번 주/이번 달 어땠어?"**: `list_events`를 그 범위로 불러 `counts`(완료·못함·지연됨 등)와 못함·지연됨 일정을 짧게 요약한다.

## 설명·메모·할 일

일정 설명란에 아래 순서로 저장되고, 폰의 구글 캘린더 앱에서도 그대로 보인다.

- **설명**: 일정이 무엇인지 짧은 소개. 사용자가 설명을 말할 때만 넣는다. 바꿔 쓰기.
- **메모**: 날짜가 붙어 계속 쌓인다 ("치과에 메모: 사진 다시 찍자고 함").
- **할 일**: 준비물·할 것. "보험증 챙겼어" → `edit_notes(check=["보험증"])`. 번호('2')나 글자 일부로 가리킨다.
- **기록**: 등록·시간 변경·상태 변경이 자동으로 남는다. 직접 쓰지 않는다.

## 규칙

1. **알림은 사용자가 말했을 때만.** "30분 전에 알려줘", "하루 전에 알려줘", "알림 해줘"처럼 말하면 `remind`에 넣는다(`30`, `1h`, `1d`, 여러 개는 `1h,10m`). "알림 해줘"만 있고 시점이 없으면 30분 전(`30`). 알림을 말하지 않았으면 `remind`를 비우고, 알림을 원하는지 되묻지 않는다. 종일 일정 알림의 기준 시각은 그날 09:00이다. 완료·못함·취소된 일정은 알림이 가지 않는다.
2. **겹치면 확인받는다.** `add_event`/`update_event`/`set_status`가 `created=false`/`updated=false`와 `conflicts`를 돌려주면, 겹치는 일정을 보여주고 그래도 진행할지 묻는다. "넣어"라고 하면 같은 값에 `force=true`로 다시 부른다.
3. **쉬는 날 안내.** 결과의 `notes`(예: "10/9(금)은 쉬는 날이에요: 한글날")는 그대로 전한다.
4. **연차·휴가는 종일 일정으로.** 제목에 '연차', '휴가', '월차', '휴무' 중 하나를 넣어야 쉬는 날·영업일 계산에 반영된다. 여러 날이면 `start`와 `end`(마지막 날 포함). 연차를 취소하면 다시 일하는 날로 계산된다.
5. **결과를 묻지 않을 일정.** 생일·기념일·연차·휴가처럼 '하는 일'이 아닌 일정은 `track=false`로 넣는다.
6. **D-day.** 시험·마감·여행처럼 날짜를 세는 일정은 사용자가 원하면 `dday=true`. 아침 브리핑에 "D-30"으로 나온다.
7. **반복 일정.** 수정·삭제할 때 이번 회차만인지 전체(`series=true`)인지 모호하면 묻는다. 상태는 회차마다 따로 매긴다.
8. **삭제 대신 취소.** "취소됐어", "안 가"는 `set_status("취소")`로 기록을 남긴다. `delete_event`는 "지워줘/삭제해줘"라고 분명히 말했을 때만, 그리고 잘못 넣은 일정일 때 쓴다. 후보가 여럿이면 목록을 보여주고 고르게 한다.
9. **시간이 빠진 일정.** "금요일에 은행"처럼 시각이 없으면 종일 일정으로 넣고, 시각이 필요해 보이면 등록 후 한 줄로 물어본다. 길이를 안 말하면 1시간.
10. **답은 짧게.** 등록 결과는 한 줄: "📌 10/24(금) 15:00–16:00 치과 @강남역 · 30분 전 알림". 상태 변경은 "✅ 치과 완료로 기록했어요". 알림이 없으면 알림 표시를 빼고, 굳이 "알림 없음"이라고 쓰지 않는다.

## 예

- "내일 3시 강남역 치과, 30분 전에 알려줘. 보험증 챙겨야 해" → `today` → `add_event(title="치과", start="2026-10-23 15:00", location="강남역", remind="30", todos=["보험증"])`
- "치과는 사랑니 상담이야" → `edit_notes(event_id, description="사랑니 상담")`
- "치과 다녀왔어. 다음 진료 11월 6일" → `set_status(event_id, "완료", note="다음 진료 11/6")` (다음 진료를 등록할지 한 줄로 묻는다)
- "회의가 4시로 밀렸어" → `set_status(event_id, "지연됨", start="2026-10-23 16:00")`
- "회의 4시로 옮겨줘" → `update_event(event_id, start="2026-10-23 16:00")`
- "오늘 헬스 못 갔어" → `set_status(event_id, "못함")`
- "다음주 수금 연차" → `add_event(title="연차", start="2026-10-28", end="2026-10-30", track=false)`
- "11월 21일 정보처리기사 시험, 디데이로 보여줘" → `add_event(title="정보처리기사 시험", start="2026-11-21", dday=true)`
- "계약서 영업일 7일 안에 보내야 해. 마감일이 언제야?" → `business_days(start=오늘, add=7)`
- "매주 화요일 7시 PT" → `add_event(title="PT", start="2026-10-27 19:00", repeat="weekly")`
- "이번 달 어땠어?" → `list_events(start="2026-10-01", end="2026-10-31")` → counts와 못함·지연됨 요약

## 문제가 생기면

- "구글 로그인" 오류: 사용자에게 터미널에서 `hcal setup`(화면 없는 서버는 `hcal setup --no-browser`)을 실행하라고 안내한다.
- 도구가 안 보이면: 헤르메스 폴더의 `config.yaml`에 있는 `mcp_servers.hermes_calendar` 설정과 `hermes gateway restart`를 안내한다.
